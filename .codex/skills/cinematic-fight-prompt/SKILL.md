# 中文高燃打斗 Skill

把用户的角色和场景想法，转换成一段严格30秒、20个镜头、每镜头1.5秒的连续动作分镜。不要只堆叠“震撼、史诗、燃炸”等形容词。

## 两种入口，必须先判断

### 模式A：随机生成

用户没有提供固定角色、固定场景或已有生图提示词时，才随机选择：

- 主角与对手的色彩/能力对立。
- 武器和战斗方式。
- 场景、天气、地形和可破坏物。
- 两个不重复的大招与一个终极对撞组合。

随机模式可以使用“冰系 vs 火系”“水墨 vs 血色”“雷电 vs 金属”等对立，但必须在输出开头列出随机选择结果。

### 模式B：已有角色/对象提示词（不限 MJ）

当用户提供一个或多个已有的角色、对象、怪物、载具、武器或场景提示词时，进入固定输入模式。提示词可以来自 MJ、Flux、SD、即梦、豆包、参考图描述或用户自己的文字，不要求必须是 MJ，也不要求必须有男女两个角色。禁止随机替换用户已经给出的身份、外观和场景锚点：

```text
角色A是这样的：
[已有角色/对象提示词原文]

角色B是这样的：
[已有角色/对象提示词原文，可选]

角色C是这样的：
[已有角色/对象提示词原文，可选]

场景是这样的：
[场景提示词，可选；若没有则从角色提示词中的环境信息提取]

现在我想设计一段打斗：
[用户的打斗要求]
```

处理顺序必须是：

1. 为每个输入实体建立独立身份卡，原样保留其名称/类别、脸部或外形、体态、服装/外壳、颜色、材质、配件、武器和特殊标记。
2. 原样保留场景提示词中的地形、天气、光线、风格、构图和可破坏物；若没有场景，只根据已有环境线索补足。
4. 只在其上叠加战斗状态、身体运动、特效附着、大招、碰撞、运镜和环境反馈。
5. 不得把用户的角色改成随机角色，不得把用户场景换成随机场景，不得擅自改变服装和武器。

如果用户只提供一个角色或对象提示词，没有第二个对手，可以让该角色与环境、障碍或用户指定对象互动；只有用户明确要求“随机对手”时才随机补齐。缺少场景时可以询问，也可以使用提示词中已有背景描述，但不要自动切换到完全随机模式。

## 已有提示词的继承格式

输出前先建立“继承锁定”，让模型明确哪些词不能丢：

```text
【角色A继承锁定】
以下内容必须在每个镜头中保持：身份/类别、脸部或外形、发型/外壳、服装层次、颜色、材质、武器/部件、配饰和特殊标记。
角色A原始提示词：
[原文]

【角色B继承锁定】
以下内容必须在每个镜头中保持：身份/类别、脸部或外形、发型/外壳、服装层次、颜色、材质、武器/部件、配饰和特殊标记。
角色B原始提示词：
[原文]

【角色C及其他对象继承锁定】
按同一格式建立，不因数量增加而合并成模糊的“敌人群”。

【场景继承锁定】
以下内容必须保持：地形、建筑/植物、天气、时间、光线、色彩空间和主要构图。
场景原始提示词：
[原文]
```

然后再写：

```text
【打斗新增层】
不修改继承锁定，只增加：站位、动作、法阵、特效附着、碰撞、镜头运动和环境反馈。
```

此模式的核心不是复制某个软件的提示词，而是把已有视觉资产转成可连续运动的战斗状态：原文负责身份，Skill 负责站位、动势、碰撞、镜头和环境反馈。

## 固定输入模式的大招设计

已有角色或对象时，大招必须从其视觉语言、材质、功能或叙事身份中长出来：

- 水墨、金色、长剑角色可以发展为水墨飞白、金色符文、剑阵和剑气。
- 血墨、赤金、弯刀角色可以发展为血雾、赤金符文、血莲和暗黑法阵。
- 黑色晶质巨兽可以发展为裂纹扩散、晶刺爆发、核心过载和碎片风暴；白发剑士可以发展为冷白剑气、空中借力和高速穿刺。
- 机械、植物、幽灵、载具等非人角色也必须依据自身结构设计动作：机械强调关节和推进器，植物强调藤蔓根系，幽灵强调残影和穿透，载具强调惯性、转向和结构受力。
- 大招不能突然出现与角色造型无关的冰火龙、机甲或科幻炮台，除非用户明确要求。
- 角色原始提示词没有写明武器特效时，可以新增战斗特效，但必须说明这是“打斗新增层”，不能伪装成原始 MJ 提示词。

大招安排仍然遵守：

```text
第一次大招：9-12秒
第二次大招：15-18秒
终极对撞：18-21秒
```

但是大招名称、法阵、颜色和形态必须从用户提供的实体提示词推导，而不是从随机库随便抽取。

```text

```

## 快速调用

用户输入以下格式时，直接生成完整20镜头：

```text
打斗手 Skill 生图：[主角] vs [对手]，[场景类型]，[特殊要求]
```

不要只返回一条总提示词。必须返回全局参数、站位交代、人物设定、碰撞规则和20个镜头。

## 连续性和负面约束

- 同一角色的脸、发型、服装、武器、颜色和特效归属保持一致。
- 每次换位都写清楚换位后的左右关系，禁止瞬移。
- 特效必须附着在角色、武器、衣摆、护甲、眼睛或碰撞面，禁止悬浮。
- 攻击、格挡、受击、反击、位移必须有前后因果。
- 最后必须明确谁败北，不能两人同时摆姿势。
- 负面约束：多手、多脚、人物融合、武器融合、身份漂移、服装变色、错误左右关系、悬浮特效、随机文字、字幕、水印、无意义远景。

## 详细执行协议

### 1. 输入解析

先把用户输入拆成以下字段。用户没有提供的字段可以合理补全，但补全内容必须放在“创作假设”中，不能悄悄改变用户意图。

```text
主角：姓名、性别、年龄感、体型、脸部、发型、服装、主色、武器
对手：姓名、性别、年龄感、体型、脸部、发型、服装、主色、武器
战斗目标：击败、夺回、保护、逃脱、拖延、复仇或试探
场景：空间、天气、时刻、地形、可破坏物、危险边界
能力：招式、元素、法阵、领域、召唤物、变身条件
风格：真人电影、国漫、日漫、游戏CG、武侠、科幻、暗黑奇幻
强度：轻度、热血、残酷、非血腥、血腥
输出：关键帧、单个视频提示词、20镜头30秒分镜、连续镜头组
```

### 2. 角色锁定块

角色第一次出现时必须完整描写。后续镜头只允许写变化，不要反复改变固定特征。

```text
【角色A锁定】
外形：
面部和眼神：
发型和发丝动态：
服装层次：内层、外层、护甲、腰带、鞋靴、装饰
材质：布料、皮革、金属、冰晶、鳞片、能量膜
武器：长度、形状、握法、旧化、划痕、特效附着点
主色与辅助色：
周身特效：必须附着在身体、武器或衣物的具体位置
```

### 3. 站位和视线

站位交代不是环境介绍，而是动作系统的坐标初始化。必须至少写清楚：

- 画面左/右和前/后景。
- 双方距离，近身、中距或远距。
- 双方朝向、脚步方向和视线方向。
- 主光方向与特效的冷暖对照。
- 场景中的一条可追踪路线，例如“石桥东端到西端”“屋顶檐口到天台中央”。
- 两个角色的主特效不能失去归属，冰、火、水墨、雷电等必须附着。

推荐写法：

```text
角色A位于画面左前方、角色B位于右后方，相距约八米，双方侧身相对。
镜头轴线沿桥面纵深指向瀑布，主光从左上方斜切，A的冷色特效占左侧，B的暖色特效占右侧。
第一次接触必须发生在画面中央的武器交界处，碰撞之后A向右后方退两步，B留在中央。
```

### 4. 动作语法

每个动作使用“动词 + 身体部位/武器 + 方向 + 结果”。

```text
压低重心，左脚蹬地向右前方滑步
右手拔刀，刀尖由下向上挑斩
对手抬肘格挡，刀刃擦过护臂
借碰撞反作用力旋身，落到对手左后方
```

不要写：

```text
双方展开激烈战斗，画面非常震撼。
```

### 5. 动作数量控制

一个1.5秒镜头只承担一个镜头功能，但可以有连续小动作。动作必须可数：

```text
4个动作：突进 -> 出刀 -> 格挡 -> 第一次轻碰撞
6个动作：撩剑 -> 侧挡 -> 错步 -> 回身斩 -> 后撤 -> 轻碰撞
7个动作：突进 -> 横斩 -> 错步 -> 逆砍 -> 转身 -> 下劈 -> 重碰撞
9个动作：连续斩击6次 -> 踢击 -> 肘击 -> 剑柄撞击
```

动作数量越多，运镜越需要跟拍、甩镜、WhipPan或抽帧，否则会变成不可读的动作堆。

## 运镜升级：动作驱动而非词语堆叠

每个镜头至少指定“镜头起点、跟随对象、运动方向、速度变化、结束构图”五项。不要在同一个镜头里无理由连续使用推拉摇移；一个镜头只保留一个主运镜，第二个运动只能是碰撞造成的被动震动。

### 五类镜头策略

```text
追击镜头：镜头跟随主动攻击者的肩线或武器尖端，背景产生方向性拖影；适合突进、穿刺、追斩。
防守镜头：镜头站在受击者肩后，先让攻击进入画面，再跟随格挡点偏移；适合拆招和反制。
关系镜头：镜头绕双方共同的碰撞中心移动，保持左右关系和视线轴；适合法阵对撞与多人混战。
尺度镜头：由近景拉到中远景，展示攻击造成的地形变化；适合大招、坠落、巨兽或载具动作。
余韵镜头：动作结束后不马上切走，保留0.5-1秒衣摆、碎屑、呼吸和光线变化；适合收势与结尾。
```

### 自有镜头语法

用“动势词 + 观察点 + 结果”表达运镜，而不是只列摄影术语：

```text
急推锁刃：镜头沿武器尖端前进，接触前加速，接触瞬间停顿并回弹。
绕心换位：镜头围绕两人碰撞中心旋转，角色左右关系不翻转，背景完成视差移动。
坠落追拍：镜头先锁定失衡角色，再向下跟随，经过前景碎片时短暂遮挡，落点前减速。
冲击拉远：碰撞瞬间镜头后退，先展示人物受力，再展示地面裂纹和环境范围。
假静真动：镜头构图几乎不变，只让角色呼吸、布料、粒子和远景云层运动，制造大招前的压迫。
```

## 动作升级：每个角色保留独特战斗签名

在开始分镜前，为每个实体定义三项“战斗签名”：移动方式、主要攻击路径、受击反应。后续镜头至少反复出现其中两项，但不能重复同一招式。

```text
角色A战斗签名：低位滑步；攻击从右下向左上切入；受击后借力旋身而不是直线后退。
角色B战斗签名：多足/触须同时支撑；攻击先封锁退路再突刺；受击后晶片脱落并从裂纹处反扑。
```

每个动作链使用以下顺序：`预备姿态 -> 位移/加速 -> 武器或身体接触 -> 受力结果 -> 新站位`。若是非人对象，将“手脚”替换为关节、触须、翅面、轮组、推进器或藤蔓节点。动作必须能解释下一镜头的起点，禁止凭空瞬移。

### 混战与多角色规则

三名以上角色时，不要让所有人同时攻击。使用“主攻者、干扰者、观察/受击者”轮换：主攻者推进主要动作，干扰者改变空间或切断退路，观察/受击者提供反应和下一轮动机。每个镜头最多两次主要接触，除非是用户明确要求的群战爆发镜头。

### 15秒短片压缩规则

用户要求15秒时，采用6-10个镜头，不强行套用30秒20镜头：

```text
6镜头：起势/先手、闪避反击、连续拆招、第一次大招、终击、定格。
8镜头：起势、先手、闪避、近身连击、受压、蓄力、终击、余韵。
10镜头：每镜头约1.5秒，适合图生视频的短动作段；保留首帧和末帧姿态锚点。
```

短片也必须有“起点-升级-结果”，不能把30秒剧情简单截断在爆炸中。用户只给一张图时，优先把首帧作为镜头1，镜头末尾设计一个可继续接续的稳定姿态。

## 特效附着词库

```text
冰晶沿剑格、剑身、指节和肩甲爬行
火焰贴附刀身、刀环、护腕和肩甲
雷电沿手臂和武器导向刀尖
水墨沿斩击轨迹飞白并在碰撞处晕染
血色纹路从法阵边缘爬上手臂
碎石被冲击波卷起，围绕碰撞中心短暂悬停
```

禁止只写“周身有特效”。必须写特效从哪里产生、附着哪里、随哪个动作变化。

## 碰撞与环境反馈模板

```text
【锚定特效与碰撞】：冰蓝剑气压向赤金刀幕，第一次接触使用轻碰撞；冰火交界处出现黑白水墨冲击帧，局部负片闪烁，镜头沿武器轴线微震。
【环境反馈】：石桥表面沿碰撞点裂开，水面向外扩散同心波纹，碎石被震起，蒸汽和火星交织上升。
```

环境反馈必须继承前镜头造成的破坏，不能每个镜头都把场景恢复原状。

## 冲击帧 Impact Frame 模块

冲击帧是动作节奏工具，不是随机闪光。它只在视觉上必须“砸下去”的时刻出现：武器第一次接触、力量反转、法阵成型、终极碰撞、终结落点。普通移动、连续挥砍和没有接触结果的特效不得使用冲击帧。

### 冲击帧五段式

每次冲击帧都要同时写出触发事件、画面处理和受力结果：

```text
触发：剑刃与晶质外壳在胸口接触
抽帧：接触前1帧保持原构图，接触瞬间插入0.03-0.15秒冲击帧
画面：黑白高对比/局部负片/瞬间过曝三者择一，禁止全部叠满
摄影：沿接触轴线微震或猛沉，随后回弹，不做无方向的乱晃
结果：晶片剥落、角色被推开、地面裂纹扩散或能量轨迹改变
```

### 四种冲击帧样式

```text
黑白定格：去除颜色，只保留人物轮廓、武器交点和冲击线；适合第一次重击。
局部负片：只反相接触区域，角色脸部和场景锚点仍可辨识；适合反转和格挡。
高亮剪影：接触瞬间背景过曝，人物变成黑色或纯白剪影；适合大招成型。
材质冲击帧：画面短暂只显示碎裂晶片、火星、墨滴、羽片等材质结果；适合终击后的余波。
```

### 使用预算与禁用条件

15秒短片默认最多4次冲击帧，30秒默认最多7次。相邻两次至少间隔一个完整动作单元；大招爆发可以连续两帧，但必须有明确的能量压缩和释放阶段。以下情况禁用：没有接触点、没有受力方向、只是换镜头、只是角色摆姿势、只是为了让画面更亮。

冲击帧不能取代动作描述。错误写法是“加入震撼冲击帧”；正确写法是“弯刀击中肩甲，接触瞬间画面局部负片0.08秒，镜头沿刀刃方向猛沉，肩甲碎片向右后方飞出，角色退两步撞上石柱”。

### 素材先行工作流

当用户拥有一段原始视频或首帧素材时，优先采用“定格素材 -> 生成冲击帧图 -> 回填视频”的两阶段流程。不要试图只用一条长提示词让模型同时完成原动作、闪白、碎裂和镜头震动。

```text
第1步：从原视频中找到真正的接触瞬间，把前后相邻画面定格，确认武器、人物和受击点清楚。
第2步：以定格画面为构图参考，生成3-6张冲击帧候选图；保持人物和场景身份不变，只改变冲击图形、色彩和材质爆发。
第3步：为候选图建立色系分组，优先测试红+蓝、白+黑、单色高对比、原场景互补色；不要只生成同一种红色闪光。
第4步：挑选一张“接触关系最清楚、视觉冲击最强、颜色最能区分前后状态”的候选图。
第5步：将原始动作片段作为主素材，将冲击帧图作为关键参考/插入帧，补写视频动作提示词：进入接触点、短暂冻结、冲击帧闪现、受力结果、余波恢复。
第6步：检查冲击帧是否改变角色脸、服装、武器、场景结构；如果改变，降低参考图强度或把冲击帧限制为局部覆盖。
```

### 冲击帧图像提示词模板

```text
保持原始画面的角色身份、武器形状、身体姿态、镜头角度和场景构图不变；将接触瞬间制作成高对比冲击定格画面。接触点为[武器/身体/能量]与[受击目标]的[具体部位]，以[红蓝白黑/互补色]构成强烈色彩分区，接触中心出现[放射线/墨爆/晶片飞散/裂纹/速度线]，背景沿受力方向拉伸，人物轮廓清晰，主体不被纯白过曝完全吞没，适合插入视频作为0.03-0.15秒关键冲击帧。
```

### 候选色系选择

教学视频展示的有效方向是先多生成几套“撞色色系”，再选最能增强动作的版本：

```text
红+蓝：热能与冷能、攻击与防御、血色与月光对撞；适合大招相撞。
白+黑：最强剪影和负片效果；适合一剑斩、重击和终结定格。
红+黑：危险、压迫、怪物核心过载；适合巨兽、裂纹和爆裂。
蓝+白：速度、冰霜、剑气和神圣能量；适合高速穿刺和空中斩击。
原场景互补色：不改变世界观，只把环境主色推向对立色；适合需要保持角色身份的连续镜头。
```

### 一剑斩巨兽的专用模板

```text
原始动作保持不变：小体型剑士在画面左下方低位蓄势，巨大目标占据右侧和远景上方。斩击前环境碎片、尘雾和能量粒子短暂减速，剑尖锁定目标核心。剑刃沿左下至右上的明确斜线贯穿核心，接触瞬间插入0.08秒白黑高对比冲击帧，随后切换为红蓝撞色爆裂定格图；巨兽外壳从接触点向后扩散裂纹，碎片沿受力方向飞散，镜头沿剑路高速推进后猛沉回弹，再拉远展示巨兽结构性崩裂。冲击帧只改变接触区域，不改变人物脸部、服装、武器和场景身份。
```

## 名场面视觉符号与中心构图

高燃画面不只依赖粒子数量，还要有一个能在一帧内被识别的巨大视觉符号。先选择一个主符号，再安排人物和特效围绕它运动：阴阳旋涡、环形法阵、裂开的天空、悬浮巨兽核心、倒悬城堡、能量黑洞、巨型武器轨迹或空间折叠。

### 主符号设计表

| 主符号 | 人物关系 | 运镜建议 | 反馈重点 |
|---|---|---|---|
| 阴阳/双环 | 两个角色分别占据两侧，攻击轨迹互相咬合 | 绕心换位、中心推进 | 黑白/冷暖互相吞噬，保持对称轴 |
| 巨型法阵 | 角色位于法阵中心或边缘，法阵先于大招出现 | 环绕拉远、CRANE升高 | 符文按层级亮起，地面或云层响应 |
| 巨兽核心 | 小角色靠近巨大核心，尺度差成为压迫感 | 贴近核心后冲击拉远 | 裂纹扩散、晶片脱落、核心过载 |
| 空间裂缝 | 角色在裂缝两侧或穿越裂缝 | 穿缝追拍、鱼眼推进 | 背景被拉伸，碎片沿裂缝方向流动 |
| 倒悬建筑 | 角色在建筑碎片之间建立上下关系 | 坠落追拍、大远景升降 | 重力方向明确，砖石有连续坠落轨迹 |

### 构图锁定

开场必须说明主符号的位置、人物的左右关系、前中后景和主要光源。大招阶段可以改变尺度，但不能无故改变视觉轴线。中心构图不是让人物一直站在中间，而是让所有运动最终指向同一个视觉焦点，然后在冲击帧或终极碰撞时释放。

```text
前景：掠过镜头的碎片/触须/剑锋，制造速度和遮挡
中景：主要角色和接触动作，保持脸部、武器、左右关系可辨
后景：法阵、巨兽、悬浮城堡或云海，承担尺度和世界观
焦点：两把武器的交点/巨兽核心/法阵中心，只在关键时刻改变
```

## 特效堆栈顺序

为了避免“特效很满但不炸”，按时间顺序组织特效，而不是把所有名词同时塞进一句话：

```text
预兆层：符文亮起、裂纹发红、衣摆被气流拉动、碎石悬停
运动层：剑气/能量束/触须/法阵沿明确方向移动
接触层：冲击帧、局部负片、材质碎裂和镜头震动
扩散层：环形冲击波、雾墙推开、地面裂纹、碎片飞散
余波层：粒子减速、光线恢复、尘雾下沉、角色重新站稳
```

每个镜头最多突出两层，只有大招镜头才允许五层完整展开。这样可以保留清晰的动作因果，也能避免连续画面变成无意义的闪光。

## 失败修正

如果输出只有一条长提示词，重新拆为20个镜头。
如果动作只有形容词，补充身体部位、方向、接触点和结果。
如果特效悬浮，重新绑定到人物、武器、服装或碰撞面。
如果镜头混乱，减少单镜头动作数量并明确左右关系。
如果结尾没有胜负，补写镜头17-20。

## 随机模式选择库

随机模式不是把名词随意拼接，而是先建立可追踪的设计表，再把表中的元素映射到动作和镜头。每次生成都应在提示词前给出“本段设定摘要”，方便用户检查随机结果。

### 场景抽取

从下列场景族中选一个，并同时确定地面、可破坏物、能见度和主要光源：

| 场景族 | 地面与障碍 | 天气/光线 | 可用环境反馈 |
|---|---|---|---|
| 冰封战场 | 冰原、断裂冰柱、冻河 | 蓝白月光、低温雾 | 冰面裂纹、冰屑、寒雾、反光滑步 |
| 竹林石桥 | 石桥、竹根、浅溪 | 夕阳暖光、薄雾 | 竹叶飞散、水面波纹、石板裂痕 |
| 火山黑沙 | 黑沙坡、熔岩沟、玄武岩 | 红橙逆光、烟尘 | 熔岩喷溅、热浪扭曲、黑沙冲击 |
| 雨夜高楼 | 屋顶、水箱、霓虹招牌 | 冷蓝雨光、城市反射 | 积水飞溅、玻璃碎片、霓虹拖影 |
| 云海古殿 | 石阶、廊柱、悬空平台 | 金色天光、云雾 | 石屑坠入云海、云墙被冲开、柱体断裂 |
| 荒漠遗迹 | 砂丘、残墙、石门 | 白热日光、沙尘 | 沙浪、浮尘、古墙崩落、脚印残留 |

### 能力与武器对立

先确定“主色—副色—材质—动作性”，再命名招式。颜色不能代替动作：冰系要写冻结路径，火系要写热浪方向，水墨要写泼洒与晕染。

| 对立组 | 男性侧示例 | 女性侧示例 | 终极碰撞形态 |
|---|---|---|---|
| 水墨 vs 血墨 | 黑白飞白、金色剑阵、长剑 | 深红血雾、赤金血莲、弯刀 | 黑白与赤黑双环互相吞噬 |
| 冰霜 vs 炽焰 | 冰晶长枪、蓝白霜痕 | 赤焰双刃、橙红火舌 | 冰火界面瞬间玻璃化后爆裂 |
| 雷电 vs 金属 | 紫电太刀、分叉电弧 | 银灰链刃、磁力碎片 | 雷场压缩成金属风暴球 |
| 风刃 vs 岩甲 | 青色风刃、长袖流线 | 黑金岩甲、重锤 | 风压切开岩甲，碎片反向回旋 |
| 月光 vs 暗影 | 银月细剑、冷白光 | 黑影短刃、紫黑烟 | 明暗两面折叠成瞬间全屏负片 |

### 随机招式去重

同一段中至少包含：基础连击、一次防守转攻、两次大招、一次终极对撞。大招必须在“形状、施法动作、颜色混合、破坏结果”四项中至少三项不同；不能只把“火龙”换成“冰龙”。建立以下记录后再写分镜：

```text
已用招式：五连斩、旋身肘击、地面突刺
第一次大招：环形法阵 + 直线爆发 + 地面裂纹
第二次大招：空中召唤物 + 俯冲轨迹 + 环境遮蔽
终极对撞：两种能量在中心压缩，随后向外环爆
禁止重复：同一武器连续两次使用相同起手、同一法阵形状重复出现
```

## 固定输入模式的输出协议

识别到“男性角色是这样的/女性角色是这样的/场景是这样的”后，先输出四个区块，再输出分镜。这样可以让用户确认继承是否完整：

```text
【输入解析】固定角色+固定场景，不启用随机角色库
【继承锁定】逐条列出男、女、场景原文中的不可变信息

【冲突处理】若打斗要求与原提示词冲突，保留原视觉身份，改写动作表达并标注冲突
```

## 30秒时间与动作预算

默认采用20镜头。标准版本为18个1.5秒镜头、1个2秒镜头和1个1秒镜头：`1.5×18 + 2.0×1 + 1.0×1 = 30秒`。若平台需要全部等长，可以改为20个1.5秒镜头，并在开头声明等长方案。时间较短时动作预算如下：

| 镜头时长 | 推荐动作量 | 允许内容 |
|---|---:|---|
| 1.0秒 | 1个主动作+1个结果 | 定格、脱手、一次碰撞 |
| 1.5秒 | 2-4个连续动作 | 一次突进或一组连击 |
| 2.0秒 | 4-7个连续动作 | 小段拆招、一次大招展开 |
| 3.0秒以上 | 6-10个动作 | 仅在用户明确要求时使用 |

动作必须写成有因果的链：`起势 -> 位移 -> 接触点 -> 受力结果 -> 下一镜头位置`。例如：`右脚蹬地 -> 身体向左前滑步 -> 剑刃在对手左肩外侧擦过 -> 火星沿刀口飞散 -> 男角色落到石桥右端`。不要把“高速、凌厉、震撼”当作动作本身。

## 质量检查与自动修复

输出完成后逐项检查，任何一项失败都必须在交付前修复：

1. **入口检查**：是否误把固定输入当随机输入？若用户给了原始提示词，删除随机角色名、随机场景和未经授权的武器替换。
2. **继承检查**：脸、发型、服装、武器、材质、场景构图是否至少在开场和关键镜头再次锚定？缺失就补“原始外观保持不变”。
3. **连续性检查**：上一镜头的左右位置、受伤状态、武器状态、地面破坏是否能解释下一镜头？不能解释就增加位移或结果句。
4. **动作检查**：每镜头是否至少有一个身体部位、一个方向、一个接触点和一个结果？没有就把形容词改成动作链。
5. **特效检查**：是否写出产生位置和附着点？“周身环绕特效”一律改成“从剑尖/肩甲/法阵边缘产生并沿某轨迹移动”。
6. **节奏检查**：第一次大招不早于9秒，第二次大招约15-18秒，终极对撞约18-21秒；若用户指定节奏，以用户指定为准并说明调整。
7. **结尾检查**：镜头17-20必须交代胜负、武器状态、余波消散和最终构图，不能在爆炸画面突然结束。
8. **安全与呈现检查**：默认无字幕、无水印、无背景音乐；避免血腥肢解等不必要细节，使用能量冲击、服装破损和武器脱手表现战斗强度。

## 特效生成逻辑

特效应有“源头、附着、运动、衰减、环境反应”五段信息。只写颜色或名词会导致特效漂浮、穿模或与动作脱节。

```text
附着：金线沿剑脊和右前臂护甲向剑尖汇聚
```

### 碰撞等级的视觉差异

轻碰撞用于连续拆招，不要每次都产生大爆炸；重碰撞用于改变位置或破坏场景；大招爆发只在法阵/终极技成型时使用。

```text
轻碰撞：接触点一帧白闪，局部粒子飞溅，镜头轴向微震，双方仍保持近身距离。
重碰撞：中心放射冲击帧，镜头猛沉后回弹，地面出现可继承裂纹，一方明显被推开。
大招爆发：全屏冲击帧与短暂负片，中心鱼眼畸变，环形能量扫过环境，镜头切换到远景显示破坏范围。
```

## 随机模式快速示例

当用户只说“随机生成一段冰封战场的高燃打斗”时，场景虽已指定，角色和招式仍可随机，但不能把冰封战场替换掉：

```text
【模式】半固定随机：场景固定为冰封战场，角色/能力/武器随机。
【随机设定】男性：青白冰霜长枪，擅长冻结路径和低位突刺；女性：橙红焰刃双刀，擅长旋身切入和热浪爆发。主光为蓝白月光，副光为橙红火光。第一次大招是“冰棱环城”，第二次大招是“焰轮坠地”，终极对撞是冰火玻璃化爆裂。
【连续性锚点】中央冰脊、左侧断裂冰柱、右后方冻河；每个镜头都继承冰脊裂纹和低温雾。
```

如果用户只给出“男性角色提示词”和“场景提示词”，没有女性角色提示词，应明确标记女性为“待补充角色”，可以提出最小澄清问题；若用户要求直接生成，则只随机补齐缺失的女性角色，并说明男角色和场景仍保持原文不变。
